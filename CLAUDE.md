# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

DocRewind is a local-first MV3 browser extension (Chromium + Firefox from one codebase) that
reconstructs and replays Google Docs/Sheets/Slides revision history entirely on-device.

## Essential Commands

This repo is **Bun-only** (`packageManager: bun@1.3.14`). Never use npm/pnpm/yarn or `npx`.
Run everything from the repository root.

```sh
bun install --frozen-lockfile   # install; bun.lock is committed and required
bun run postinstall             # wxt prepare — generates .wxt/ types; needed before compile/build
bun run dev                     # WXT dev server (dev:firefox for Gecko)
bun run build                   # → .output/chrome-mv3   (build:firefox → .output/firefox-mv3)
bun run compile                 # tsc --noEmit
bun run check                   # biome check --write .  (CI uses non-writing `bunx biome ci .`)
```

Tests are split across **three runners** — pick the one that owns the file you changed:

```sh
bun run test:logic              # Bun tier: every pure module under lib/core/** (imports bun:test)
bun run test:run                # Vitest tier: lib/platform/** + test/**  (bun run test = watch)
bun run test:e2e                # Playwright tier: e2e/** against .output/chrome-mv3
bun run test:coverage           # 85% per-file line/function floor on the gated cores
```

Targeted runs:

```sh
bun test lib/core/docs/decoder/decode.test.ts          # one pure-core file
bun test lib/core/docs/decoder -t "tombstone"          # filter by test name
bunx vitest run test/popup.test.tsx -t "opens options" # one Vitest file / case
```

The remaining gates CI runs, in this order after `compile` and `check`:

```sh
bash scripts/check-pure-core.sh              # purity guard (see Critical Gotchas)
bash scripts/check-no-foreign-hosts.sh       # static network-isolation lint
bash scripts/check-coverage-gate-disjoint.sh # coverage-gate honesty guard
bun run hooks                                # prek run --all-files (hooks:install to wire git hooks)
```

`test:e2e` needs a fresh `bun run build` plus `bunx playwright install --with-deps chromium`
(`e2e/fixtures.ts` pins `channel: "chromium"`). `bun run lint:firefox` needs `build:firefox` first.

## Architecture Overview

Three layers with a hard, mechanically enforced boundary:

| Layer | Location | May import |
| --- | --- | --- |
| Pure core | `lib/core/**` | other pure core only — no `#imports`, no `browser.*`, no `wxt` |
| Platform adapters | `lib/platform/**` | pure core + `idb` / `#imports` / `browser.*` |
| Runtime + UI | `entrypoints/**`, `components/**` | everything |

Import via the `@/*` alias (tsconfig `paths` maps it to the repo root), not deep relative paths.

**Retrieval → replay flow.** `entrypoints/docs.content.tsx` mounts an activation affordance in a
shadow root (it never auto-loads history) and `sendMessage("startRetrieval", …)`.
`entrypoints/background.ts` is the **only** place in the codebase that calls `fetch` — it wires the
live `ChunkFetcher`/discovery adapters into the pure `lib/core/retrieval/orchestrator.ts` and writes
`rawChunks` + `checkpoints` to IndexedDB. The replay page then spawns
`entrypoints/replay/parse.worker.ts`, which opens its **own** idb connection, reads `rawChunks`,
dynamic-imports exactly one per-kind pipeline from `lib/core/worker/pipeline-{docs,sheets,slides}.ts`,
and posts run-tagged results back; the page verifies the run tag before publishing derived rows.

**IndexedDB write ownership is partitioned and must stay that way** (a Worker is a separate realm
with its own connection): background owns `rawChunks`/`checkpoints`; the replay page owns decoded/
snapshot/timeline publication rows. This is documented at the top of `lib/core/store.ts`.

**Three editor kinds.** `DocumentKind = "doc" | "sheet" | "slides"` (`lib/core/domain/kind.ts`) is a
boundary-only tag — it appears in URL parsing, endpoint builders, messaging, storage and viewport
selection, and **never** inside a core's op union or model, so each core stays closed-world over its
own grammar. Each kind has `lib/core/<kind>/decoder/` + `lib/core/<kind>/reconstruction/`; the
model-agnostic snapshot/replay machinery is shared in `lib/core/replay-core/` (`spine.ts` takes
injected `createModel`/`cloneModel`/`applyRevision`; `meta.ts` is the common metadata supertype).

**Storage split.** Settings only → `lib/platform/settings.ts` (`storage.defineItem` over
`storage.local`). Bulk/queryable data → `lib/platform/db.ts` (`idb`). Never `localStorage`.

**Generated / do-not-edit.** `.wxt/` and `.output/` are generated and gitignored. `manifest.json` is
generated by WXT from `wxt.config.ts` — the privacy invariant (`permissions: ["storage"]`,
`host_permissions: ["*://docs.google.com/*"]`) is declared there and re-audited on the shipped zips
by `scripts/verify-manifest.sh`. `public/icon/*.png` are committed on purpose; regenerate only with
`./scripts/generate-icons.sh` when `public/icon/docrewind.svg` changes.

## Implementation Decisions

| Situation | Preferred approach | Avoid |
| --- | --- | --- |
| Cross-context call | Add a method to `ProtocolMap` in `lib/platform/messaging.ts` | Raw `browser.runtime.sendMessage`, untyped payloads |
| Network request | The adapter inside `defineBackground` in `entrypoints/background.ts` | `fetch` anywhere else — `check-no-foreign-hosts.sh` and the purity guard both fail |
| Persisting data | `RevisionStore` via `createIdbStore()` for bulk; `settings.ts` items for preferences | A second `openDB` call, `localStorage` |
| User-visible text | Add it to the catalog in `lib/core/i18n/strings.ts` | Inline English in a component or in `render.ts` |
| Dark-mode branching | Pure `resolveDark` (`lib/core/theme.ts`) + `useThemeSync` (`components/common/theme-sync.ts`) | `matchMedia`/`document` checks in components; `dark:` color variants (semantic `--dr-*` vars already flip) |
| Testing a pure module | `bun:test` file next to the source under `lib/core/**` | Vitest — `vitest.config.ts` excludes those dirs, so the test would silently not run |
| Testing a component or storage adapter | Vitest in `test/**` or beside the file in `lib/platform/**` | `bun test` — it cannot resolve jsdom/Solid JSX setup |

## Common Change Workflows

**Changing decode or reconstruction semantics**

1. Edit the kind's `decoder/` or `reconstruction/` module under `lib/core/<kind>/`.
2. Bump the matching `version.ts` constant (`PARSER_VERSION`, `SHEETS_PARSER_VERSION`,
   `SLIDES_PARSER_VERSION`) — `lib/platform/db.ts` keys derived-cache invalidation off it and
   retains raw chunks so no network re-fetch is needed.
3. Update or add the hand-derived fixture in `lib/core/fixtures/` (read its README first).
4. `bun run test:logic` then `bun run test:coverage`.

**Adding a cross-context message**

1. Declare the payload interface and the method in `ProtocolMap` (`lib/platform/messaging.ts`).
2. Register the handler inside `defineBackground` in `entrypoints/background.ts`.
3. Call it with `sendMessage` from the content script / page.
4. Extend `test/background.test.ts`, then `bun run test:run`.

**Changing the IndexedDB schema**

Bump `DB_VERSION` in `lib/platform/db.ts` and handle the upgrade path, keep `lib/platform/db.memory.ts`
in step, then run `bun run test:run` — `lib/platform/db.contract.ts` is one behavioral suite executed
against both backends, so they are provably interchangeable.

## Testing and Validation

Pure-core tests are hand-derived, not snapshots of the implementation: never compute an expected
value by running `apply.ts` and pinning its output (see `lib/core/fixtures/README.md` on the
three-tier acceptance scheme). E2E is network-free — `e2e/fixtures.ts` fulfills every
`docs.google.com` request from sanitized fixtures and **throws** on any unmodelled path rather than
returning an empty 200, so a renamed endpoint fails loudly.

## Critical Gotchas

- **`browser.*` and `fetch` must stay inside `defineBackground`/`main(ctx)`**, never at module top
  level — top level runs in WXT's Node build context and throws.
- **A new file inside a coverage-gated dir is subject to the 85% per-file floor from its first
  commit** (Bun applies `coverageThreshold` per file, not to the aggregate, and has no per-file
  override). If a file genuinely cannot meet it, add its specific path glob to
  `coveragePathIgnorePatterns` in `bunfig.toml` with a justification; do not lower the global
  threshold. Read the `[test]` comment block in `bunfig.toml` before touching coverage config.
- **`prek` blocks direct commits to `main`** (`no-commit-to-branch`) and enforces Conventional
  Commits via a `commit-msg` hook — work on a branch.
- TypeScript runs with `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess`: give settings
  items concrete fallbacks rather than optional fields, and narrow indexed access explicitly.
- `biome.json` sets `suspicious.noExplicitAny: "error"` — model untyped boundaries as `unknown` plus
  a runtime guard (see `isDocumentKind`).

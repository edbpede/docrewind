# AGENTS.md

This file provides guidance to AI coding agents when working with code in this
repository.

DocRewind is a Bun-only, WXT + Svelte 5 MV3 browser extension that reconstructs
Google Docs/Sheets/Slides revision history locally. No backend, no telemetry.

## Setup

`bun install --frozen-lockfile` runs `postinstall` → `wxt prepare`, which
generates `.wxt/` (tsconfig base, WXT globals, `#imports`). Without it `bun run
compile`, the build, and Vitest all fail to resolve. Run `bun run postinstall`
after any WXT/config change.

## Commands

| Task | Command |
| --- | --- |
| Typecheck | `bun run compile` |
| Lint + format (writes) | `bun run check` — CI uses non-writing `bunx biome ci .` |
| Pure-core tests (Bun) | `bun run test:logic` |
| Component/platform tests (Vitest) | `bun run test:run` |
| E2E (Playwright) | `bun run build` first, then `bun run test:e2e` |
| Coverage gate | `bun run test:coverage` |
| All git hooks | `bun run hooks` (`prek`) |

Single test:

```sh
bun test lib/core/domain/kind.test.ts -t "case name"     # pure core
bunx vitest run test/popup.test.ts -t "case name"        # component/platform
bunx playwright test e2e/replay-smoke.spec.ts            # e2e (needs a build)
```

Never run bare `bun test` at the repo root: it globs `test/*.test.ts`, which
import `vitest` and fail. Use `bun run test:logic` or an explicit path.

## Three test tiers

| Tier | Location | Runner |
| --- | --- | --- |
| Pure core | `lib/core/**` | `bun:test`, enumerated in `test:logic` |
| Platform + UI | `lib/platform/**`, `test/**` | Vitest |
| Assembled extension | `e2e/**` | Playwright against `.output/chrome-mv3` |

Adding a new pure directory under `lib/core/` requires **two** edits: add its
path to `test:logic` in `package.json` **and** to `test.exclude` in
`vitest.config.ts`. Skip the second and Vitest picks the files up and dies
trying to resolve `bun:test`.

## Purity guard (`scripts/check-pure-core.sh`, CI + pre-commit)

- All pure dirs listed in the script's `BASE_DIRS`: no `#imports`, no
  `browser.`, no `wxt` import.
- `lib/core/retrieval`, `lib/core/worker`, `lib/core/docs-url` additionally:
  no `fetch(`, no `new Worker`, no `globalThis`.

The single live `fetch` adapter is `entrypoints/background.ts`; the Worker shell
is `entrypoints/replay/parse.worker.ts`. Need I/O from a pure module? Inject it
as a dependency (see `ChunkFetcher` in `lib/core/retrieval/transport.ts`).

## Network isolation (`scripts/check-no-foreign-hosts.sh`, CI + pre-commit)

`docs.google.com` is the only fetchable host. The script fails on any other
`http(s)://` literal in code under `lib/` or `entrypoints/` (comment lines are
exempt) and on `XMLHttpRequest`/`WebSocket`/`EventSource`/`sendBeacon`/
`importScripts` anywhere. `github.com` is allowed as a display-only anchor href.
A genuinely new fetch target means editing `wxt.config.ts` host permissions, the
script's `allowed_host`, and `e2e/network-isolation.spec.ts` — never just the
lint list.

## Generated files — do not hand-edit

- `manifest.json` — generated by WXT; change `wxt.config.ts` instead.
- `.wxt/`, `.output/` — build output.
- `public/icon/{16,32,48,96,128}.png` — committed but derived from
  `public/icon/docrewind.svg`; regenerate with `./scripts/generate-icons.sh`.

## Layout and boundaries

- `lib/core/**` — pure, browser-free logic. `lib/platform/**` — the only place
  browser APIs live (idb, `browser.storage`, messaging). `entrypoints/**` — WXT
  entrypoints. `components/**` — Svelte UI, at the repo root, not under `lib/`.
- Each editor has its own closed-world core: `lib/core/{docs,sheets,slides}/
  {decoder,reconstruction}`. Shared machinery lives in `lib/core/replay-core`
  (snapshot/replay spine), `lib/core/timeline`, `lib/core/summary`.
- `DocumentKind` (`lib/core/domain/kind.ts`) is a boundary-only tag: it routes
  which core, transport prefix, and viewport a document uses. Never add it to a
  core's op union or model.
- Imports use the `@/*` alias rooted at the repo root (`@/lib/…`,
  `@/components/…`).

## Cache versioning

Three independent levers — bump the matching one or stale data is served:

- `DB_VERSION` in `lib/platform/db.ts` — IndexedDB schema shape.
- `PARSER_VERSION` (`lib/core/docs/decoder/version.ts`),
  `SHEETS_PARSER_VERSION`, `SLIDES_PARSER_VERSION` — bump on any change to that
  editor's decode or reconstruction semantics. They invalidate independently.

`lib/platform/db.ts` and `lib/platform/db.memory.ts` must stay behaviorally
identical; one suite (`lib/platform/db.contract.ts`) runs against both, so
change them together.

## Coverage gate lives in two files

`test:coverage`'s path arguments in `package.json` define what is gated;
`coveragePathIgnorePatterns` in `bunfig.toml` defines what is dropped from the
report. `scripts/check-coverage-gate-disjoint.sh` fails CI if they overlap. The
85% line/function floor is applied **per file**, so a new partially-covered file
inside a gated directory fails from its first commit. To exempt one, add its
specific path glob to `coveragePathIgnorePatterns` with a one-line
justification; do not lower `coverageThreshold`.

## Conventions

- Every source file starts with `// SPDX-License-Identifier: AGPL-3.0-or-later`.
- WXT contexts: keep all `browser.*`/`fetch`/DOM access inside
  `defineBackground()` / `main(ctx)`. Module top level runs in WXT's Node build
  context and throws.
- Color: use the semantic tokens from `uno.config.ts` (`bg-canvas`, `text-ink`,
  `bg-brand`, …). Do not write `dark:` variants for color — the CSS variables
  flip under `.dark`.
- New UnoCSS shortcut: add it to the `shortcuts` const in `uno.config.ts`
  (`safelist` derives from its keys). A bare utility used by only one entrypoint
  must be added to `safelist` by hand or it is dropped from the shared CSS chunk
  and renders unstyled.
- Conventional Commits are enforced by the `commit-msg` hook. Install hooks with
  `bun run hooks:install`; that also enables `no-commit-to-branch main`, so work
  on a branch.
